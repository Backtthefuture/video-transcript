# 微信视频号 · 三种交付

> 给 agent 看。用户贴了微信视频号链接（`weixin.qq.com/sph` / `channels.weixin.qq.com`）时读这份。
> B 站 / 抖音 / 小红书 / YouTube / 播客不要走这里，继续用仓库根目录 [SKILL.md](../SKILL.md) 原流程。
> 从 SKILL.md 点过来：[视频号三种交付](../SKILL.md#视频号三种交付先读这个)。

转写在用户电脑上跑（FunASR，不需要 API Key）。PDF 用 [Kami](https://github.com/tw93/Kami) 羊皮纸中文长文排。文件名用视频原标题。

---

## 一句话分流

| 用户怎么写 | 交付 |
|---|---|
| 什么都不写，或写「逐字稿」「逐字稿版本」 | **默认。** 整理过的口语逐字稿，直接发在对话里。**不排 PDF。** |
| 「文字PDF」（旧称「文字版本」） | 同一份口语稿，排成 Kami 羊皮纸纯文字 PDF。文件名 = 官方标题 |
| 「截图PDF」（旧称「截图版本」） | 同一份口语稿 + 从视频里抽的关键帧，混排进羊皮纸 PDF。文件名 = 官方标题 |

旧别名必须认：`文字版本` = 文字PDF，`截图版本` = 截图PDF，`逐字稿版本` = 逐字稿。

三种共用**一份**口语稿，差别只在怎么交出去。

---

## 共用：正文是「他怎么说的」

三种交付的正文是同一份口语逐字稿。

做：

- 补标点、分说话人、改对专有名词
- 保留原话原意，不改观点
- 封面最多放 2–4 句**原话金句**（从正文里摘，不要改写成广告语）

不做（正文里永远不要出现）：

- 第三人称导读、执行摘要、Takeaways、要点列表当正文
- 用自己的话重述整段发言
- 把独白改成「他谈到了… / 本文介绍…」
- 给视频号再跑 `make_optimized.py` 出「整理优化版」（那是 B 站等平台的流程）

**反例（禁止再犯）：** 把得到「马想」的独白改成第三人称概述 + Takeaways 再排进截图PDF。那不是逐字稿。

机器预整理稿（`*_预整理.md`）可以当底稿：标点、碎句已经处理好。你只修说话人、专有名词、明显错词。小标题若像「核心观点 / 总结」这种概述腔，删掉或改成说话人自己的话。不要把预整理稿再扩写成另一篇文章。

---

## 官方标题（三种都用）

用解析到的**视频原标题**，不要自己起短标题。

- 去掉话题标签（`#ListenHub` 这类）
- 标题里的明显错字要改，文件名一起改（例：`ListebHub` → `ListenHub`）
- 同一份标题用在：封面、HTML `<title>`、PDF 元数据、页脚、附件文件名

---

## 默认 / 逐字稿：对话里交稿

1. 按 [SKILL.md](../SKILL.md) 阶段 3 跑转录（**不要**加 `--keep-video`）
2. 读 `preorganized_path`，按上面「他怎么说的」修一版
3. **在对话里完整贴出口语稿**（Markdown，不要包代码块）
4. 末尾一行写落盘路径
5. **到此结束。不要调 Kami，不要出 PDF。**

用户后来又说「排成文字PDF / 截图PDF」：复用这份已经修好的口语稿，不要重跑识别（除非用户说重跑）。截图PDF 若本地还没有 MP4，再去下视频。

---

## 文字PDF

口语稿与默认模式完全相同，只是排成 PDF。

1. 转录（不要 `--keep-video`）
2. 修好口语稿
3. 用 Kami **中文长文**（`long-doc.html` / long-doc），羊皮纸 + 墨蓝
4. 按本文「PDF 版式」排
5. 附件文件名 = 官方标题（去标签、改错字）+ `.pdf`
6. 对话里简短说明「文字PDF 已排好」，附上 PDF；不要再把全文贴一遍，除非用户要

## 截图PDF

口语稿与上面两份相同。**只多一件事：往稿子里插入视频关键帧。**

### 视频从哪来

帧必须从**视频文件本身**抽，不要用分享页封面、头像、海报。

转录时加 `--keep-video`：

```bash
"$VT_PY" "$VT_HOME/scripts/transcript.py" "<视频号链接>" --keep-video
```

看 stderr 的 `----- VT_OUTPUTS -----` 里有没有 `video_path`。缓存命中但没有 MP4 时：

- 用配套 [`video-download`](https://github.com/Backtthefuture/video-download) 只下视频，**不要**为了拿 MP4 就 `--force` 重跑识别
- 用户明确说重跑时才加 `--force`

### 怎么抽帧

场景检测 + 按时间补帧，两路一起，再人工筛选。

```bash
# 场景切换
ffmpeg -i "<video.mp4>" -vf "select='gt(scene,0.28)',showinfo" -vsync vfr \
  "$FRAMES/scene_%04d.jpg"

# 按时间补点（短视频大约每 8–12 秒一张，避免漏掉屏幕）
ffmpeg -i "<video.mp4>" -vf "fps=1/10" "$FRAMES/tick_%04d.jpg"
```

用 `ffprobe` 把每张图对应到时间戳，文件名改成 `MM-SS.jpg` 或 `HH-MM-SS.jpg`（例如 `00-42.jpg`）。不要用 `frame_001.jpg` 这种看不出时间的名字。

### 选哪些帧

- 优先：屏幕、文档、幻灯片、示意图、关键数据
- 说话人特写：只在章节转换处留 1 张
- 短视频大约 **25–45** 张；太少会漏屏幕，太多会变成连环画
- 丢掉：黑场、重复脸、模糊过渡、分享页封面

### 插到稿子哪里

- 插在**正在讲这句**的旁边，不要集中堆在文首或文末
- 图注 = **时间戳 + 一句该时刻在讲什么**（用口语稿里的话，不要另写导读）
- 例：`00:42　他指出 ListenHub 不是又一个播客 App`

然后按「PDF 版式」用 Kami 长文排出去。文件名同样用官方标题。

## PDF 版式（文字PDF 与 截图PDF 相同）

用 [tw93/Kami](https://github.com/tw93/Kami) 中文长文，不要自己发明一套短文档模板。

| 项目 | 规格 |
|---|---|
| 正文 | 24px，行高 1.68，左对齐，首行不缩进 |
| 段 / 发言间隙 | `margin-bottom: 20px`（不要 12px） |
| 金句 / 引用 | 约 27px |
| 图注 | 16–18px |
| 标题 | h1 ~36 / h2 ~30 / h3 ~26 |
| 颜色 | 羊皮纸底 + 墨蓝字 |
| 中文字体 | TsangerJinKai02；排出后跑 Kami `--check-fonts` |
| 页数 | 多几页没关系，不要为了压页数删正文 |

找不到 Kami 就先装再排，不要用浏览器「打印成 PDF」凑合。

### 访谈（两个及以上说话人）——两种 PDF 都要套

- 提问人：红色名牌 `#E23B2F`，白字加粗，后面紧跟全角冒号；**整句问句加粗**
- 嘉宾：黑色加粗姓名，**不要**红牌；答句用常规字重
- 每一轮之间 20px 间隙

### 独白

- 不要红牌
- 同样 20px 段间距
- 仍然用第一人称原话，不要改成第三人称叙述

---

## 绝对不要

- 视频号默认模式去排 PDF
- 三种模式各写一份不同的正文
- 正文写成概述 / 导读 / Takeaways
- 截图PDF 用分享页封面冒充关键帧
- 给 PDF 另起一个「更好记」的短标题
- 为了拿视频把已经转好的稿子 `--force` 重跑一遍识别
