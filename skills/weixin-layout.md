# 微信视频号：口语稿与 PDF 交付

视频号链接的媒体获取沿用 video-download；正文经夸克网盘官方 Skill 取回。先按根目录 [SKILL.md](../SKILL.md) 核对文件对应、云端原始回答与正文完整性，再制作本页所述交付。云端正文未经逐句听校时，不得称为准确逐字稿。

## 三种交付

| 用户需求 | 交付 |
| --- | --- |
| 未指定，或说“逐字稿” | 对话中给口语稿和来源、核对状态；不默认做 PDF |
| “文字 PDF” | 同一份已检查口语稿排版成纯文字 PDF |
| “截图 PDF” | 在同一份稿件中加入实际查看过的视频关键帧，再排 PDF |

“文字版本”“截图版本”“逐字稿版本”分别按上面三种处理。三种交付复用同一份经过检查的正文，不为不同版式重写观点。

## 正文处理

- 先读完整原始回答、预整理稿与 polish_brief；检查是否摘要、拒绝、缺段或明显截断。发现问题时保留 response_needs_review，先不要排版。
- 仅纠正有依据的错词、标点和分段。保留第一人称、数字、原有顺序与口语表达；低确信处标待核。
- 不能推测说话人、人名或句级时间戳。访谈里只有来源明确的人名才标注；未知发言人保持未知。
- 标题优先使用视频原题；删除文件名不允许的字符即可。原文与整理稿分开保存。

## 默认口语稿

将核对后的稿件完整发在对话里，附来源、文件对应方式及抽查或听校程度。若正文尚未核实完整性，就明确写“云端正文已取回，完整性待核对”。

## 文字 PDF

基于同一份口语稿排版。若已安装 Kami，可用其中文长文版式；交付前回读 PDF，确认没有漏段、乱码和意外重排。没有可用的排版工具时，先交付文字稿并说明 PDF 尚未完成。

## 截图 PDF

本 Skill 默认保留下载的媒体。只从已核对来源且哈希相符的原视频抽帧，实际看图后选择屏幕、文档、幻灯片或重要画面；不要用分享页封面冒充视频帧。

云端正文没有可靠句级时间轴。只能依据已查看的视频画面与能核实的内容安排图文位置，不能按推测时间自动配图或编造时间戳。若本地媒体缺失，按 SKILL.md 的修复规则处理，不用 --force 重新请求正文。排版后检查每张图和邻近文字的对应关系。

PDF 可沿用 [Kami](https://github.com/tw93/Kami) 中文长文版式，建议羊皮纸底、墨蓝字，并检查中文字体。文件名用视频原标题的安全版本。

## 状态说明

分别报告媒体来源与对应、云端正文取回、人工抽查或听校范围、轻校对、PDF 排版与图文匹配状态。任何一步未完成，都不要把整个交付标为完成。
